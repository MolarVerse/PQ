Releases and Hotfixes

These steps use the GitHub website.

Normal release

  1. Open Actions and select Create Release PR.

  2. Click Run workflow. Choose main, enter an unused version such as v1.2.3, leave restore unchecked, then click Run workflow again.

  3. Open the generated PR to main. Link its issue, review and merge once checks pass. The release branch starts from dev.

Hotfix

  1. On Code, select main. Use the branch dropdown to create hotfix/short-description from it.

  2. Make the correction and add a fragment such as changes/user/bugfix.short-description.md.

  3. Open New pull request with base main and compare your hotfix branch. Title it Hotfix-X.Y.Z: short description, where X.Y.Z is the latest release with the patch number raised by one. Link its issue, review and merge once checks pass.

Opening the PR starts Release Lifecycle automatically. It takes the version from the title and rejects any other than the next patch. After merge, publication waits for BUILD and LINT.

Check a run

Open Actions, then Release Lifecycle. Fixing code on the PR branch starts a new run. For temporary failures, use Re-run failed jobs. Check the version and commit under Releases after success.

The Run workflow button requires write access and the workflow on main. Use CLI fallback if the GitHub interface is unavailable.
